# Cortex Bridge v0.5 verification map

This file maps release-evidence counters to executable tests. The machine-readable result is `v0.5.0.json`.

## Automated suites

- `backend`: every test discovered under `tests/`.
- `frontendUnit`: Vitest component tests plus the runtime, privacy, image and build contracts.
- `e2e`: Playwright fixture tests against the shipped interface.
- `a11y`: Axe, keyboard, reduced-motion and responsive checks at 375, 768 and 1440 pixels.

## Acceptance counters

### Twenty fixture missions

`tests/test_transport_fixture.py` contains the numbered 1–20 transport contract: selection, lock, send, streaming, stable extraction, blocker states, restart, pause, cancellation, uncertain delivery and manual fallback. All twenty must pass in the same backend run.

### Ten cold dual-writer runs

`frontend/e2e/dual-conversation.spec.ts` reloads the application and repeats the complete A/B/third-writer scenario ten times. Each run proves distinct A and B sends, rejection of a third writer, and preservation of the third draft and attachment.

### Six crash and recovery points

The six counted points are:

1. `test_loop_mock.LoopTestCase.test_08_restart_recovery_requires_explicit_resume`
2. `test_missions_api.MissionsApiTestCase.test_08_restart_recovery_surfaced`
3. `test_playwright_driver.PlaywrightDriverTest.test_startup_failure_is_evicted_and_factory_recovers`
4. `test_transport_session_isolation.MissionPersistenceFailureTest.test_sqlite_update_failure_fails_mission_and_releases_exact_lease`
5. `test_transport_session_isolation.MissionRouteSessionIsolationTest.test_runtime_construction_failure_fails_creation_and_releases_lease`
6. `test_transport_session_isolation.MissionStopQuiescenceTest.test_cancel_keeps_slot_until_browser_and_background_task_quiesce`

These points cover stored recovery state, surfaced server recovery, browser-start failure, database-write failure, runtime-construction failure and cancellation while browser work is still quiescing.

## Live boundary

Owner-authorized acceptance used the real signed-in ChatGPT tab in Google Chrome through the unpacked Cortex extension. It passed one conversation, two isolated writers, refusal of a third writer with its draft preserved, one text-file upload, one explicitly authorized screenshot upload, closed-tab recovery and three autonomous mini-site missions. No account detail, private title, conversation content or unredacted live screenshot was committed.

These technical results do not imply that the consumer-site automation is an officially supported OpenAI integration. Provider-terms review remains an owner release decision. The release verdict is therefore `RELEASE_CANDIDATE_READY_FOR_OWNER_APPROVAL`, not a provider endorsement or an automatic publication decision.

## Clean macOS lifecycle

The clean lifecycle uses a fresh `HOME` and `CORTEX_HOME`, real locked Python packages, the packaged extension manifest, the owned-process lifecycle, `doctor`, an idempotent reinstall and manifest-based uninstall. The normal install does not download Playwright Chromium. The service returned HTTP 200, accepted the WebSocket upgrade only for a `chrome-extension://` origin, stopped cleanly and released its port. A foreign listener was refused and preserved. Private temporary paths and logs are not committed.

## Commit convention

The `commit` field in `v0.5.0.json` identifies the audited source commit. The manifest may be committed immediately afterward because a file cannot contain the hash of the commit that contains itself. A release tag should include both by pointing to the evidence commit whose first parent is the audited source commit.
