## Suggested Alternatives

- Remove `tsx` after the release baseline moves to a Node version whose native TypeScript stripping covers the test files, or compile those files before Node’s test runner executes them.
- Do not replace Uvicorn merely to make the table shorter. Reassess maintainership and security contact quarterly; a replacement must pass the same loopback, shutdown, packaging and performance suites.
- Keep `strict-allow-scripts=true`, review `npm approve-scripts --allow-scripts-pending --json` after every lock change, and reject any new lifecycle script until its exact package and version are reviewed.
- Run `npm audit`, the locked Python installation, secret scanning and current/history privacy gates for every release candidate.
